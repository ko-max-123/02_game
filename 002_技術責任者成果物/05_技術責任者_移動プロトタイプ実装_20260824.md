## 1. 決定

正式技術方針のUnity／URP／C#で、山田・K1と中央工業帯デモフィールドを用いた2.5D移動確認環境を新規実装した。横方向主体、限定奥行き、ジャンプ、Space長押し飛行、固定奥行きカメラ、地面判定、落下復帰、操作HUDを一つの生成シーンへ統合する。

本決定は技術実装だけを対象とし、シナリオ、章構成、キャラクター設定、戦闘仕様の決定は変更しない。

## 2. 操作・挙動の技術契約

| 項目 | 確定値・方式 |
|---|---|
| 主移動 | `A/D`、X方向、7.0m/s |
| 限定奥行き | `W/S`、Z方向、3.5m/s、Z=-2.5～+2.5mへClamp |
| 対応区画 | このデモフィールド全域を奥行き移動対応区画として扱う。量産ステージでは同契約を区画単位へ分割する |
| 斜め入力 | 入力ベクトルを最大1へ正規化し、斜め移動の速度増加を禁止 |
| ジャンプ | `Space`短押し、目標高2.2m、重力-24m/s² |
| 飛行開始 | 空中で`Space`を0.18秒以上保持 |
| 飛行 | 上昇加速度20m/s²、上昇速度上限5.5m/s |
| JET ENERGY | 最大100、飛行中28/秒消費、停止0.65秒後から22/秒回復 |
| 地面判定 | `CharacterController.isGrounded`＋足元`OverlapSphereNonAlloc`。Player本体と子階層Colliderを明示除外 |
| 落下復帰 | Y<-8mでスポーン位置へ自動復帰、`Backspace`で手動復帰 |
| カメラ | Orthographic、Size 6.2、X/Yだけ追従、Z=-16mを毎フレーム固定、俯角8度 |
| HUD | 操作ガイド、GROUND/AIRBORNE/FLYING、レーンZ、JET状態、ENERGY、採用アセットを表示 |

移動方式は`CharacterController`へ統一した。限定奥行きの境界を数値契約として保持でき、Rigidbody外力によるレーン逸脱を避け、フレームレート非依存の入力検証を行えるためである。

生成処理は再実行可能とし、既存ファイルの削除APIを使用しない。デザイン原本も削除・変更しない。

## 6. 検証結果

| 検証 | 結果 | 証跡 |
|---|---:|---|
| Unityなし静的検証 | 41/41 PASS、WARN 0、ERROR 0 | `Tools/Validate-Prototype.ps1` |
| Unityシーン再生成 | 終了コード0 | `TestResults/setup-final.log` |

EditModeでは、入力正規化、レーンClamp、ジャンプ速度、飛行ゲート、JET ENERGY、固定奥行きカメラ、落下復帰に加え、生成シーン内の正式Player、表示・衝突フィールド、HUD、カメラを検査した。

地面判定については、生成シーン上でPlayerを離床させ、`Grounded=false`になることと、同条件で0.18秒のSpace長押し後にJET許可が`true`になることを検証した。これにより自身の`CharacterController`を地面として誤検出しないことを確定した。
