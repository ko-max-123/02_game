# プロデューサー方針・追加設定

## 商品コンセプト

### 仮タイトル

**YTC: Deliver Tomorrow**  
日本語副題：**YTC ― 明日を届ける者たち ―**

### 30秒説明

近未来の小規模PMC「ytc」で働く山田となり、新型攻殻装甲K1を操る2.5Dアクション。射撃と近接、飛行と環境装備を使い分け、任務先から武器・部品・兵器流出の証拠を持ち帰る。日常の配送任務はやがて、戦争そのものを商品として生み出す計画との戦いへつながる。

### 独自性

- 3Dメカアクションを横スクロールの読みやすさで遊べる。
- 射撃と近接を相性で切り替える明確な戦闘判断。
- 装備収集が、環境攻略と物語上の兵器調査を兼ねる。
- 世界を救う巨大軍ではなく、15人の小さな会社が主役。
- 暗い軍事世界の中で「仕事として人を守る」温度を保つ。

## ターゲット

- **中心層**：15歳以上、アクション、メカ、装備ビルド、協力PvEが好きなプレイヤー。
- **副次層**：横スクロールアクションは好きだが、複雑な3Dカメラ操作が苦手なプレイヤー。
- **プレイスキル幅**：Story難易度で物語中心、Veteran以上で装備相性とアクション中心。
- **対象外**：競技PvP、極端な装備ロスト、長時間の毎日ログインを求める設計。

## 対応プラットフォーム方針

- 初期ターゲット：Windows PC、キーボード・マウスとコントローラー。
- 設計解像度：1920×1080。16:9を基準にしつつ、主要UIはウルトラワイドでも中央安全域へ置く。
- 目標パフォーマンス：推奨環境60fps、最低環境30fps。入力判定はフレームレートに依存させない。
- 将来の家庭用展開を妨げないよう、セーブ、入力、UI、文字サイズをハードコードしない。

## 販売・運営方針

- 買い切り型を基本とする。
- 装備性能を販売する課金、ランダム有料ガチャ、課金専用強化素材は採用しない。
- 発売後コンテンツを作る場合は、まとまった追加フィールド・短編物語、または外観パックとする。
- オンライン協力は本編完成を遅らせる場合、発売後の独立マイルストーンへ分離する。
- サービス終了で本編が遊べなくならないよう、全ストーリーをオフライン対応にする。

## レーティング・表現

- 想定対象年齢：15歳以上相当。
- 銃撃、爆発、負傷は描くが、切断、内臓、過度な流血は描かない。
- 人間敵は「戦闘不能」と表現し、死体損壊をゲーム報酬にしない。
- 民間人被害を軽いスコア演出や笑いに使わない。
- 実在国家、民族、宗教を悪役の記号として直接流用しない。
- テロや戦争を背景にしても、現実の直近事件をなぞる宣伝は行わない。

## 物語トーン

**基調：ハードな世界の中の職業的な優しさ。**

- 任務中は緊張感、帰還後は食事、整備、請求書など小さな日常を描く。
- ytcは善良だが万能ではない。契約、資金、信用の制約を受ける。
- 敵を倒せばすべて解決するのではなく、証拠、救助、公開、責任追及を決着に含める。
- 真壁の理屈には理解可能な入口を作るが、民間被害の責任を相対化しない。
- 「笑顔」は毎回口にするギャグではなく、会社が難しい判断をする時の基準として使う。

## アート方針

### キーワード

- 近未来工業
- 修理痕のある実用品
- 小さな会社の温かい橙
- 企業技術の冷たい白
- ORPHEUSの無機質な赤黒ノイズ

### シルエット

- K1：中量、人間らしい可動域、左右非対称の試験部品。
- 旧式機甲兵：幅広く重い、拳と背部冷却器が目立つ。
- ORPHEUS：人間を守る空間を削った細い胴体、危険な逆関節や過可動。
- ytc装備：共通の橙ラインと、小さな笑顔マーク。派手な企業ロゴより現場マーキング。

### 色の役割

| 色 | 用途 |
|---|---|
| 橙 | ytc、味方、帰還、修理可能 |
| 青 | 通常操作、装置、シールド |
| 黄 | 環境危険、注意、非致死目標 |
| 赤 | 即時攻撃危険、敵対、ガード不能 |
| 白緑 | LARK、安全認証、救済可能な機械 |
| 赤黒ノイズ | ORPHEUS侵食、偽信号 |

色だけに情報を依存せず、形、アイコン、音を併用する。

## サウンド方針

- K1の動作音は、重量感のあるサーボ音と装着者の呼吸を組み合わせる。
- アーマー被弾、シールド被弾、HP被弾を明確に別音にする。
- 対機甲弾には通常弾と異なる乾いた発射音、赤い照準警告、着弾前の短い高音を付ける。
- ytc本社では工具、ポット、無線、倉庫扉など生活音を使う。
- ORPHEUSの音楽は複数の機械音声が同期していく構造。LARK使用で個々の声へ分解する。
- ボイスがなくても字幕だけで成立する台本を作る。

## UI・UX方針

- 戦闘HUDは「生存」「現在武器」「エネルギー」「目標」の順で視線優先度を付ける。
- 装備画面では数値増減だけでなく「重装甲に有効」「砂漠では熱が危険」など行動変化を表示する。
- 新システムは実際に使う短い区画で教え、長い説明文を先に読ませない。
- 一度見たチュートリアルはデータベースから再確認できる。
- ボス敗北後の再戦画面から、装備変更、難易度変更、敵情報確認へ直接移動できる。
- 売却・分解時はプリセット品、最高品質、Signature、未登録特性を警告する。

## 会話・カットシーン方針

- 通常会話：30～90秒。
- 章開始・終了ムービー：原則3分以内。
- 最終章など重要場面のみ5分まで。
- 移動中無線は戦闘開始で一時停止し、終了後に続きから再生する。
- 操作可能な場面でプレイヤーを長時間歩かせるだけの会話を避ける。
- 固有名詞を一場面に三つ以上初出させない。
- 章終了時に「何が分かったか」「次に何をするか」を一文ずつ明確にする。

## 本社ハブ

ytc本社はメニューを物理空間へ対応させる。ただし、毎回歩かなくてもクイックメニューで移動できる。

| 場所 | 担当 | 機能 |
|---|---|---|
| 作戦室 | 高城・御厨 | ストーリー、マップ、任務選択 |
| 整備庫 | 火野 | 装備、強化、分解、K1改修 |
| 倉庫 | 森川 | 店、保管、弾薬、売却 |
| 医務室 | 伊吹 | 状態説明、訓練、人物会話 |
| 通信室 | 天城・戸塚 | 敵図鑑、証拠解析、協力プレイ |
| 応接室 | 小野寺・荻原 | サブ任務、評判、契約ログ |
| 食堂 | 全員 | 章間会話、短い日常イベント |
| 訓練室 | 神谷・佐伯・辰巳 | コンボ練習、DPS計測、ボス再戦 |

## サブコンテンツ

### 人物任務

- 各ytcメンバーに1～2本。
- 強さのために必須ではなく、その人物の仕事と価値観を知る内容。
- 報酬はSignature装備、支援効果、外観。

### 指名手配

- メインボスとは別のElite敵。
- フィールド既存ギミックを新しい組み合わせで使う。
- 全討伐でBLACK RAIL残党の後日談を解放。

### 異常任務

- フィールドクリア後に出現する可変ルール任務。
- 例：低重力、弾薬半減、常時吹雪、敵味方電撃伝播、Elite増加。
- 一週間限定にせず、取得後はいつでも遊べる方式を基本とする。

### 証拠ボード

- 証拠品を時系列と関係線で表示。
- メインストーリーに必須の線は自動接続。
- 任意ログを集めると、人物会話と背景説明が増える。
- プレイヤー自身に総当たり推理を要求するミニゲームにはしない。

## 制作スコープ

### P0：戦闘プロトタイプ

- 一対一の射撃・近接・飛行
- アーマー／HP
- 敵の距離維持・射撃
- DownとRetry

### P1：バーティカルスライス

- 第1章Stage 01～05
- K11、VS-01、K1標準ジェット
- ゴライアスT
- 基本UI、チェックポイント、簡易本社整備画面
- 仮モデルでも最終品質に近い入力感とカメラ

### P2：コアループ完成

- 第2章まで
- ドロップ、帰還、強化、売却、証拠品
- 護衛と対機甲弾ボス
- セーブ、難易度、入力設定

### P3：コンテンツ生産可能状態

- フィールド1～3
- 共通敵AIとギミック部品化
- 会話、任務、ドロップのデータ駆動化
- ステージ制作の性能・QA基準確立

### P4：本編完成

- 全20章、10フィールド、100ステージ
- 人物任務、クリア後任務
- ローカライズ可能な全文字列管理

### P5：将来機能

- オンライン協力
- 追加短編、追加フィールド
- 家庭用展開

オンラインをP1～P3の完了条件に含めない。

## 優先順位

変更・削減が必要な場合、次の順で守る。

1. 移動、射撃、近接、飛行の手触り。
2. アーマーと武器相性の分かりやすさ。
3. Story 1～4と最終決着を含む物語の連続性。
4. 装備収集・強化・帰還ループ。
5. 10フィールドの環境差。
6. ytcメンバーの主要会話。
7. サブ任務、指名手配、収集ログ。
8. オンライン協力。

100ステージを守るために中身を薄める必要が生じた場合は、先にステージ数を減らし、一つの良いステージを守る。フィールド10面は目標仕様であり、品質より上位ではない。

## 主要リスクと対策

| リスク | 症状 | 対策 |
|---|---|---|
| 飛行で地上戦を無視 | 敵を越えて進める | 対空敵、エネルギー、空中報酬。見えない壁は最小限 |
| 射撃だけが安全で最適 | 近接を使わない | 重装甲、弾薬、装甲破壊、近接報酬 |
| 近接が理不尽 | 接触・画面外被弾 | 明確な予告、キャンセル、カメラ制御 |
| 装備厳選疲れ | 倉庫整理が主時間になる | 特性数制限、フィルター、確定品、天井 |
| 物語固有名詞が多い | 陰謀を追えない | 各章二つまで、証拠ボード、自動要約 |
| 15名が覚えられない | 顔と役割が一致しない | ハブ機能と人物を一対一で結ぶ |
| 100ステージ量産 | 繰り返し感 | 代表ギミック、再利用の組合せ、品質ゲート |
| オンラインで物語矛盾 | K1が複数存在 | ゲスト外観をYC支援フレーム化 |
| 強制敗北への不満 | 実力を否定された感覚 | 第3章のみ、専用UI、評価を下げない |
| 数値インフレ | 初期武器が無価値 | 強化追従、倍率上限、役割差を維持 |

## 品質基準

### 戦闘ステージの完成条件

- 初見プレイヤーが主目標を理解できる。
- 画面外攻撃の予告が聞こえ、見える。
- 推奨装備なしでも代替ルートか現地対策でクリアできる。
- チェックポイントからボス再戦まで30秒以内。
- 落下・挟まり・護衛停止から復帰できる。
- 30fpsと60fpsで攻撃判定と回避時間が同じ。

### 章の完成条件

- 章開始時に目的が明示される。
- 新しい敵またはギミックを一つ教え、章ボスで応用する。
- 章終了時に物語が一段進む。
- 確定報酬が次章の問題へ役立つ。
- 本社の会話が最低3名分更新される。

## テレメトリ方針

プレイ改善に必要な匿名イベントだけを収集対象とする。

- ステージ開始・成功・失敗・離脱地点
- 選択難易度とアシスト
- ボス敗北原因、使用武器、装備構成
- チュートリアル再表示
- ドロップ取得・売却・分解
- 救助、非致死、証拠回収率

会話内容、個人ファイル、必要のない入力履歴は収集しない。収集の有無と目的を設定画面で説明する。

## ローカライズ方針

- 日本語を原文とし、英語展開を想定する。
- UI文字は日本語基準の1.5倍幅まで伸びても崩れない。
- 台詞内へ変数を直結しすぎず、語順変更可能な単位で管理する。
- `ytc`、`K1`、`LARK`、`ORPHEUS`、`BLACK RAIL`は全言語共通表記。
- 「攻殻装甲」は英語で`Combat Shell`、「機甲兵」は`Shell Trooper`を暫定訳とする。

## 続編・追加章への余地

- 本編で真壁とORPHEUSの主計画は必ず解決する。
- クリア後に残せるのは、流出済み兵器、BLACK RAIL残党、他社の模倣計画。
- 美緒の救出やytcの濡れ衣を次回作へ持ち越さない。
- 続編フックのために本編の満足を犠牲にしない。
