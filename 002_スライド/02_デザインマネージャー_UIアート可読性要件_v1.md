# YTC: Deliver Tomorrow — UI・アート・可読性要件 v1

- 担当決裁: 2. デザインマネージャー
- 状態: デザイン領域確定
- 用途: 最終統合スライド用素材
- 対象: Windows PC、1920×1080／16:9基準、キーボード・マウス／コントローラー

## 結論

本作の視覚設計は、**「修理しながら人を守るytc」と「人間の余白を削るORPHEUS」の対比**を軸にする。戦闘情報は色だけに依存させず、**色・形・文字・動き・音のうち常に2系統以上**で伝える。

## 1. K1／ytc／ORPHEUSの視覚差

| 対象 | シルエット | 素材・表面 | 色・マーキング | 動き・音 | 伝える印象 |
|---|---|---|---|---|---|
| K1 | 中量級。人間らしい可動域。左右非対称の試験部品 | 工業塗装、露出した交換部、修理痕 | 中立色を基調にytc橙ライン。小さな笑顔マーク | 重いサーボ音、装着者の呼吸、着地時の重量感 | 未完成だが、人が使い続ける実用品 |
| ytc | 人が立てる余白、丸みのある安全形状、現場道具が見える | 使い込まれた金属、布、木、補修テープ | 温かい橙。個人名・整備印・手書きの現場表示 | 工具、ポット、無線、倉庫扉など生活音 | 小さな会社の温度、帰還、修理可能性 |
| ORPHEUS | 細い胴体、逆関節、過可動。人間を守る空間がない | 継ぎ目の少ない冷たい外装、異常に均一な面 | 無彩色＋専用の赤黒ノイズ。ytc橙を使わない | 複数機械音声の同期、予測不能な微動、位相ずれ | 効率化が人間性を侵食する不気味さ |

決定事項:

- 橙はytc、味方、帰還、修理可能性に限定する。
- 赤黒ノイズはORPHEUS侵食と偽信号だけに使用する。
- K1は「格好よい完成品」ではなく、交換・修理・人の手入れが読める主役機にする。
- ORPHEUSの危険性は赤色だけで示さず、逆関節、過可動、同期音、ノイズ形状を併用する。

## 2. 戦闘HUDの情報優先度

視線優先度は **生存 → 現在武器 → エネルギー → 目標** とする。

| 優先 | 情報 | 表示要件 |
|---:|---|---|
| 1 | 生存 | アーマー、HP、重大状態異常を同一視線帯へ置く。アーマー被弾・シールド被弾・HP被弾は形と音を分ける |
| 2 | 現在武器 | 武器名、残弾、リロード、重装甲への有効／不利を表示。武器切替直後だけ拡大し、常時はコンパクトにする |
| 3 | エネルギー | ジェット／シールド等の共通消費資源を、残量と回復開始の両方が分かる形で表示する |
| 4 | 目標 | 主目標を1行で常時表示。副目標と証拠回収は主目標より弱い階層にする |

追加要件:

- 即時危険はプレイ領域の近くへ出し、画面端の方向矢印、攻撃種別アイコン、警告音を併用する。
- ガード不能攻撃は赤い破断ひし形＋短い高音。通常攻撃と色だけで区別しない。
- 画面外攻撃は方向と着弾までの段階を示し、雪・砂・煙の中でも輪郭を失わない。
- 第3章の唯一の強制敗北区間では専用UIを使用し、通常の評価UIを出さず、結果評価も下げない。「離脱／生存が目的」であることを開始時に明示する。
- 主要HUDは16:9とウルトラワイドの中央安全域へ収め、UIスケールを80～140%で変更可能にする。

## 3. 装備画面の情報優先度

装備画面は「数値の大小」ではなく、**次の任務で行動がどう変わるか**を最初に伝える。

1. ビルドの役割: 射撃／近接／防御／飛行／環境対策
2. 任務適性: 主な敵防御、環境タグ、推奨対策との一致
3. 重要な変化: 「重装甲に有効」「砂漠では熱が危険」などの平文
4. コストと制約: 装備コスト、弾薬、重量、同時装備不可
5. 詳細数値: 比較差分と計算内訳

操作要件:

- 比較時は増減値に加え、攻撃・防御・環境の3カテゴリで影響を要約する。
- プリセット品、最高品質、Signature、未登録特性の売却・分解時は二段階警告を出す。
- ミッション選択から推奨装備を確認し、装備変更後に同じ任務へ戻れるようにする。
- ボス敗北後は「再戦」「装備変更」「難易度変更」「敵情報」を同じ再戦画面から選べるようにする。

## 4. 色・形・音の共通言語

| 意味 | 主色 | 必須の非色情報 | 音の方針 |
|---|---|---|---|
| ytc／味方 | 橙 | 丸みのある盾＋実線輪郭 | 短い上昇音、無線系の実音 |
| 帰還／修理可能 | 橙 | 帰還矢印／工具／笑顔マーク | 工具系の実音 |
| 通常操作／装置 | 青 | 円形＋操作ボタンの文字／記号 | 中立的な確認音 |
| シールド | 青 | 六角形＋シールドアイコン | 硬質な反射音 |
| 環境危険 | 黄 | 三角形＋斜線パターン＋危険名 | 低速の反復警告 |
| 注意 | 黄 | 感嘆符＋注意文 | 単発の注意音 |
| 非致死目標 | 黄 | 拘束／救助アイコン＋「非致死」ラベル | 柔らかい確認音 |
| 敵対 | 赤 | 尖った敵マーカー＋敵種アイコン | 敵捕捉音 |
| 即時攻撃危険 | 赤 | 発生源から伸びる方向矢印＋攻撃種別 | 短く鋭い警告音 |
| ガード不能 | 赤 | 破断ひし形＋「ガード不能」ラベル | 着弾前の短い高音 |
| LARK／安全認証／救済可能 | 白緑 | 二重円、チェックまたはリンク形状 | 分離して聞こえる単音 |
| ORPHEUS侵食／偽信号 | 赤黒ノイズ | 非対称グリッチ枠、信号欠損、専用ラベル | 同期する複数機械音声 |

共通ルール:

- 色だけで意味を伝える表示は禁止する。
- 判読が必要な本文、数値、操作ラベルと背景は4.5:1以上、重要な大型表示・アイコン輪郭は3:1以上のコントラストを確保する。装飾要素のみ例外とし、例外部分へ情報を持たせない。
- 味方／敵、操作可能／危険は輪郭形状とアイコンでも識別できるようにする。
- 色覚プリセット、彩度調整、敵味方アウトライン変更を設定に用意する。
- 警告音には字幕または方向表示を用意し、音だけに依存させない。
- プレイヤーが立てる足場は背景との明度差を確保し、背景物と当たり判定のある物を同じシルエットにしない。

## 5. チュートリアル色ルールの競合解決

旧案の「青い床＝飛行」「黄色い床＝武器切替」は廃止する。黄色は環境危険・注意と競合するため、操作種別には使用しない。

確定案:

- チュートリアル床は中立の白／灰とし、進行方向だけを淡い実線で示す。
- 飛行練習は青い操作リング＋翼／上向き矢印＋ローカライズ可能な操作名「飛行」＋実入力表示で示す。
- 武器切替は青い操作端末＋交差する武器／循環矢印＋ローカライズ可能な操作名「武器切替」＋実入力表示で示す。
- 黄色は落下、熱、感電、可動設備などの注意帯に限定する。
- 新操作は実際に使う短い区画で教え、成功した操作だけを即時に肯定表示する。
- 一度見た説明はデータベースから再確認でき、再表示／非表示を設定できるようにする。

これにより、青は「操作可能」、黄は「注意」という全体ルールを維持しながら、操作の違いをアイコンと文字で識別できる。

## 6. 主要画面の要件

| 画面 | 最初に答える質問 | 必須情報・導線 |
|---|---|---|
| ミッション選択 | 何をし、何に備えるか | 主目標、環境タグ、主な敵、防御タイプ、推奨装備、確定報酬 |
| 戦闘HUD | 生き残り、次に何をするか | 生存、武器、エネルギー、目標、方向警告 |
| 装備／整備 | この装備で行動がどう変わるか | 任務適性、行動変化、コスト、比較、保護警告 |
| 再戦 | 何を変えれば再挑戦できるか | 再戦、装備、難易度、敵情報。ボスまで30秒以内 |
| 本社クイックメニュー | どこで何ができるか | ハブ機能と担当者の対応。歩行せず直接移動可能 |
| 証拠ボード | 何が判明し、何が未確認か | 時系列、関係線、主線の自動接続、任意ログの区別 |
| 設定／アクセシビリティ | 自分に読める・操作できる状態か | UI倍率、字幕、色覚、アウトライン、振動、点滅、入力再割当 |

## 7. アクセシビリティ・演出安全

- 字幕は話者名、ytc内の役割、方向情報を必要に応じて表示する。重要会話は戦闘開始で一時停止し、終了後に続きから再生する。
- 字幕サイズ、背景濃度、話者色、効果音字幕を変更可能にする。
- 赤黒ノイズはORPHEUSの固有表現として残すが、点滅強度・画面揺れ・色収差を個別に弱められるようにする。
- 重要警告で高速ストロボを使わない。明滅、振動、画面揺れだけで状態を伝えない。
- 入力表示はキーボード・マウス／コントローラーを自動追従し、再割当後の実キーを表示する。
- 操作名、警告名、状態名は固定英語にせず、全文字列をローカライズ可能な単位で管理する。
- UI文字列は日本語基準の1.5倍幅まで伸びても、重なりや切れが起きない構造にする。

## 8. 最終統合スライドへの推奨構成

1. **人の手が残るK1とytc、余白を削るORPHEUS** — 3者の視覚対比
2. **戦闘HUDは「生存→武器→エネルギー→目標」で迷わせない** — HUD優先順位
3. **色に頼らず、形・文字・音を重ねて危険を伝える** — 共通言語と色覚対応
4. **チュートリアル色競合は、青い操作リング＋固有アイコンで解消する** — 旧案と確定案
5. **装備画面は数値より先に、次の任務で変わる行動を示す** — 装備・主要画面要件
