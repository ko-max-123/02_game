# コア運用 v4

## 通常作業

1. 自分のタスクを確認。
2. 必要資料だけ読む。
3. `IN_PROGRESS` にする時点で作業ブランチを登録する。
4. 初回pushと同じ作業ターン内にDraft PRを作る。
5. 作業する。
6. 他領域が必要なら担当へ委譲。
7. 回答を受けて続行。
8. 必要なら校正。
9. 完了。

## ブランチ・PR管理

1. 変更を伴う `IN_PROGRESS` タスクは、`01_アクティブタスク.md` に作業ブランチとDraft PRを登録する。
2. Draft PR本文には、担当、関連Issue、対象範囲、現在できること、未達、検証方法、次のゲートを書く。
3. 未完成でもDraft PRを作る。完成してから初めてPRを作る運用は禁止する。
4. PRのない作業ブランチは未登録作業とし、正式な進捗、依存解除、レビュー、完了判定の根拠にしない。
5. 作業の節目、BLOCKED化、依存解除、検証追加のたびにDraft PR本文またはコメントを更新する。
6. 専門判断と承認は従来どおり各専門責任者が行う。マネージャーはブランチ・PR・Issue・依存関係の対応だけを管理する。
7. merge前に、担当成果物だけであること、必要な承認と検証が揃っていること、他担当の未コミット変更を含まないことを確認する。

## 巡回

巡回は `08_巡回スケジュール.md` に従う。

巡回時は:
1. 自分の確認対象だけ見る。
2. 新規・更新だけ優先する。
3. 更新がなければ即終了する。
4. 001_設定資料を巡回目的で読まない。

## 依頼経路

第一選択:
直接委譲

第二選択:
GitHub Issue

## 禁止

- 30分巡回
- 全Issue巡回
- 全共有フォルダ巡回
- 全設定資料再読
- 全員同時稼働
- 中間PPTX乱発
